# UI-SPEC v2 — پنل پیامک ادمین ترنم (`poshaktaranom.com/admin/sms`)
استودیو UI · ۱۴۰۵/۰۸/۰۵ · نسخه v2 **امتداد** `../ui/UI-SPEC.md` است (توکن‌ها، badgeها، مودال، RBAC، معیارهای سراسری v1 همچنان معتبرند و تکرار نمی‌شوند). ماکاپ‌ها: `screens/*.html` (از `build_v2.py`، با پوسته و CSS نسخه v1)، تصاویر `png/<screen>-360|1440.png`. هیچ کدی در مخزن تغییر نکرد؛ تصویر AI ساخته نشد.

## ۰. سراسری (تأکید/افزوده)
RTL-first (`dir=rtl`، فقط ویژگی‌های منطقی CSS: `margin-inline-*`، `inset-inline-*`، `border-inline-start`)؛ Vazirmatn 400/700؛ input ≥16px (جلوگیری از zoom در iOS)؛ هدف لمسی ≥44px؛ 360→1440px بدون اسکرول افقی صفحه؛ WCAG 2.2 AA. شماره‌ها/کدها با `.ltr`.
تب‌ها (نگه‌داشته): داشبورد، ارسال تکی، ارسال انبوه، قالب‌ها، مخاطبان، گزارش‌ها، لغو و سیاه، فعالیت‌ها، تنظیمات.

## ۱. کامپوننت‌های جدید
- **AudienceSourceSelector**: چک‌باکس چندگانه ۳ منبع (عمده `.com`، خرده `.ir`، همکاران بازاریاب) با شمارش هر منبع. dedupe بر اساس شماره نرمال‌شده (`09xxxxxxxxx`). حذف لغو/لیست سیاه **همیشه روشن و غیرقابل‌خاموش**.
- **SegmentBuilder**: ردیف شرط = فیلد/عملگر/مقدار (عملگر و ورودی بر اساس نوع فیلد)؛ ترکیب «و» (AND) در v2. فیلدها: منبع، شهر/استان، تاریخ آخرین سفارش، تعداد سفارش، جمع مبلغ، وضعیت همکار (فعال/غیرفعال/در انتظار)، برچسب‌ها، تاریخ عضویت. فیلدِ بی‌معنا برای یک منبع → راهنمای «فقط روی همکاران اعمال می‌شود». «ذخیره به‌عنوان سگمنت» (پویا، در لحظه ارسال دوباره ارزیابی می‌شود) + انتخاب سگمنت ذخیره‌شده.
- **RecipientPreviewPanel** (sticky در دسکتاپ، نوار پایین چسبان در موبایل): کل انتخاب → −تکراری → −لغو/سیاه → −بدون رضایت تبلیغاتی → −شماره نامعتبر → **گیرنده نهایی**؛ پارت هر پیام؛ کل پارت = مصرف اعتبار؛ هزینه ریالی = «نامشخص» + برچسب «برآورد» تا قیمت واحد معلوم شود. `role=status aria-live=polite aria-atomic`؛ debounce ~۴۰۰ms؛ عدد قبلی تا نتیجه جدید کم‌رنگ می‌ماند. «دیدن نمونه ۲۰ گیرنده» (موبایل ماسک‌شده برای نقش‌های غیرمدیر).
- **PartCounter**: UCS-2 فارسی: ≤۷۰ نویسه = ۱ پارت، بیشتر = ⌈n/۶۷⌉؛ «لغو11» شمرده می‌شود؛ با متغیرها **بیشترین طول پس از جایگذاری** ملاک است. (متن تماماً GSM/لاتین: ۱۶۰/۱۵۳ — تأیید backend لازم.)
- **VariableChips**: درج متغیر با کلیک/کیبورد (جایگزین drag، SC 2.5.7)؛ هشدار برای گیرندگان بدون مقدار + مقدار جایگزین.
- **ScheduleField**: «هم‌اکنون» یا تاریخ جلالی + ساعت تهران؛ خارج ۰۸:۰۰–۲۱:۰۰ → خطای درون‌خطی + دکمه «انتقال به اولین زمان مجاز»؛ بنر «مبنای رسمی تأیید نشده». ارسال طولانی که از ۲۱:۰۰ بگذرد ادامه‌اش به ۰۸:۰۰ بعد موکول و «برآورد پایان» نشان داده می‌شود.
- **ConfirmDialog**: `alertdialog`، فوکوس اولیه «انصراف»، تایپ تعداد گیرنده برای فعال‌شدن دکمه (مانند v1)، بالاتر از آستانه → «درخواست تأیید مدیر».

## ۳. موبایل
<1024px منو ☰؛ <768px تک‌ستون؛ ردیف شرط عمودی؛ پنل پیش‌نمایش به نوار پایین چسبان (گیرنده + پیامک + «بعدی») تبدیل؛ جدول‌ها در `.tablewrap` یا کارت. نوار چسبان نباید فوکوس را بپوشاند (SC 2.4.11 — `scroll-padding-bottom`).

## ۴. دسترس‌پذیری
fieldset/legend برای منابع و زمان؛ دکمه حذف شرط با `aria-label` مشخص؛ پیش‌نمایش live polite (نه assertive)؛ خطاها `aria-invalid` + `aria-describedby`؛ رنگ هرگز تنها نشانه نیست؛ `prefers-reduced-motion`.

## ۶. سؤالات باز
1. قیمت ریالی هر پارت (و تفاوت خط خدماتی/تبلیغاتی)؟ تا آن زمان «برآورد/نامشخص».
2. اولویت داده در dedupe وقتی یک شماره در چند منبع با نام/شهر متفاوت است (پیشنهاد: عمده > همکار > خرده)؟
3. ساعات ۰۸–۲۱ — مبنای رسمی هنوز تأیید نشده.
4. داده سایت خرده `.ir` چگونه به `.com` می‌رسد (API/همگام‌سازی/DB مشترک) و تازگی آن؟
5. رضایت تبلیغاتی برای همکاران بازاریاب چگونه ثبت شده است؟
6. آستانه تعداد برای تأیید مدیر؟
7. منطق OR/گروه‌بندی شرط‌ها لازم است یا AND کافی است؟
8. ارسال تکی به شماره‌ای خارج از هر ۳ منبع مجاز است؟
