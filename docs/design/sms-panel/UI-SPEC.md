# UI-SPEC — پنل پیامک ادمین ترنم (Site-B2B)
استودیو UI · ۱۴۰۵/۰۸/۰۴ · منابع ورودی: `../ui-brief.md`، `../spec.md`. هیچ مخزن، سایت زنده یا حسابی دست نخورد.
ماکاپ‌ها: `screens/*.html` (خودکفا، CSS درون‌خطی، فونت محلی `fonts/` با fallback به Tahoma/system) · تصاویر: `png/<screen>-360.png` و `-1440.png` (headless shell موجود Playwright، بدون نصب جدید) · مولد: `build.py` (ویرایش و `python3 build.py`).

## ۰. اصول سراسری
- `lang="fa" dir="rtl"`؛ ویژگی‌های منطقی CSS (`inset-inline-start`، `border-inline-start`)؛ شماره موبایل/کد/شناسه با `.ltr` (`direction:ltr; unicode-bidi:plaintext`).
- **واکنش‌گرا با mobile-first**: پایه یک ستونه؛ ≥۷۶۸px گریدهای ۲/۳ ستونه؛ ≥۱۰۲۴px منوی کناری ثابت ۲۴۰px (زیر آن دکمه ☰). ⚠ بریف «دسکتاپ اول» گفته بود و درخواست شما mobile-first؛ CSS به روش mobile-first نوشته شده و چیدمان دسکتاپ اولویت محتوایی دارد.
- ارقام فارسی در نمایش؛ input موبایل ارقام فارسی/عربی/لاتین و `+98`/`0098` را می‌پذیرد (نرمال‌سازی سمت سرور طبق spec ۲.۲). تاریخ جلالی، ساعت تهران.
- هدر ثابت: کارت اعتبار (عادی / زرد زیر آستانه / قرمز ناکافی / «نامشخص» + تلاش مجدد) + وضعیت اتصال provider (sms.ir · egress).
- هر صفحه: loading (skeleton + `aria-busy`)، empty، error (+ تلاش مجدد)، no-permission ۴۰۳ با نام نقش لازم.
- عملیات مخرب/پرهزینه: دکمه `danger`، همیشه با تأیید؛ «انصراف» فوکوس پیش‌فرض.

## ۲. کامپوننت‌ها (`screens/states.html`)
- **Badge نوع**: OTP آبی «رمز یکبار مصرف»، خدماتی سبز، تبلیغاتی نارنجی — همیشه متن + رنگ (نه فقط رنگ).
- **Badge وضعیت** (۹): در صف، در حال ارسال، ارسال‌شده، تحویل، عدم تحویل، ناموفق، ردشده، نامشخص (حاشیه خط‌چین)، لغوشده (خط‌خورده) ↔ `QUEUED, SENDING, SENT, DELIVERED, UNDELIVERED, FAILED, SKIPPED, PENDING_UNKNOWN, CANCELLED`. در جدول `aria-label="وضعیت: …"`.
- **کارت اعتبار**: ۴ حالت؛ واحد «پیامک» (مثلاً «اعتبار: ۱۲٬۴۵۰ پیامک»)؛ آستانه هشدار هم بر حسب پیامک.
- **پیش‌نمایش گوشی**: حباب پیام + «🔒 لغو11» قفل‌شده (غیر از OTP).
- **مودال تأیید**: `role="alertdialog"`، `aria-modal`، trap فوکوس، Esc = انصراف، بازگشت فوکوس به دکمه آغازگر.
- **شمارنده نویسه/پارت**: `aria-live="polite"`؛ قاعده UCS-2: ≤۷۰ = ۱ پارت، بیشتر = ⌈n/۶۷⌉؛ «لغو11» در شمارش لحاظ می‌شود.

## ۳. صفحات
### ۳.۱ داشبورد — `dashboard.html`
چیدمان: ۵ کارت KPI (ارسال امروز، نرخ تحویل ۷ روز، در صف، ناموفق، لغوهای جدید) → نمودار روزانه (SVG با `role=img` + جدول جایگزین) → جدول کمپین‌های در حال اجرا/زمان‌بندی‌شده با «توقف»/«لغو زمان‌بندی».
حالات: skeleton، خالی «هنوز پیامکی ارسال نشده»، خطا + تلاش مجدد.
پذیرش: KPIها با کیبورد قابل پیمایش؛ «توقف» مودال تأیید باز می‌کند.

### ۳.۲ ارسال تکی — `single-send.html`
نقش: اپراتور فقط خدماتی؛ بازاریاب/مدیر پیامک/مدیر کل خدماتی و تبلیغاتی (تبلیغاتی با رضایت، لغو11 قفل، ساعات مجاز و rate limit — بدون override).
فرم (گیرنده با جستجوی مشتری/موبایل، نوع: OTP غیرفعال/خدماتی/تبلیغاتی، قالب یا متن آزاد، متغیرها، متن) + پیش‌نمایش گوشی زنده (≥۱۰۲۴ کنار فرم، موبایل زیر آن).
حالات و microcopy:
| حالت | پیام |
|---|---|
| شماره نامعتبر | «شماره موبایل معتبر نیست. نمونه درست: ۰۹۱۲۱۲۳۴۵۶۷» (inline، `aria-invalid`) |
| لیست سیاه | «این شماره در لیست سیاه است (دامنه: همه). ارسال ممکن نیست.» |
| لغوکرده | «این مشترک با «لغو۱۱» انصراف داده است. فقط پیام‌های الزامی سفارش جاری مجاز است.» |
| بدون رضایت | «برای پیام تبلیغاتی رضایت صریح لازم است…» |
| نقش اپراتور + تبلیغاتی | گزینه «تبلیغاتی» غیرفعال با توضیح «فقط بازاریاب، مدیر پیامک و مدیر کل» |
| خارج ساعت (۴۲۲) | «ارسال تبلیغاتی فقط {شروع} تا {پایان} به وقت تهران مجاز است.» (از تنظیمات؛ پیش‌فرض ۰۸:۰۰ تا ۲۱:۰۰) + «زمان‌بندی برای اولین پنجره مجاز» |
| rate limit (۴۲۹) | «تعداد درخواست‌ها زیاد است. لطفاً N ثانیه دیگر…» |
| در حال ارسال | دکمه غیرفعال «در حال ارسال…» (جلوگیری از دوبار کلیک) |
| موفق | «پیامک ارسال شد. شناسه: …» |
| ناموفق | پیام فارسی از `code` سرور + «تلاش مجدد» |
| نامشخص | «ممکن است ارسال شده باشد؛ تکرار نکنید.» — بدون دکمه تلاش مجدد |
پذیرش: خطاها با `role=alert` اعلام شوند؛ فوکوس پس از submit ناموفق به اولین فیلد خطادار برود.

### ۳.۳ ارسال انبوه — wizard (`campaign-wizard.html`)
Stepper (`aria-current="step"`): مخاطب → پیام → زمان → بازبینی → تأیید → تأیید مدیر.
1. مخاطب: تب لیست/سگمنت/CSV؛ drag&drop + دکمه انتخاب فایل (جایگزین کیبوردی، SC 2.5.7)؛ نتیجه معتبر/تکراری/نامعتبر + دانلود خطاها؛ خطای CSV (>۵۰٬۰۰۰ ردیف یا ستون ناقص).
2. پیام: قالب، نوع، چیپ متغیرها، ۵ پیش‌نمایش شخصی‌سازی‌شده.
3. زمان: اکنون/زمان‌بندی؛ تقویم جلالی + ساعت تهران؛ ساعات غیرمجاز disabled با برچسب «غیرمجاز».
4. **بازبینی (گام ۱ تأیید)**: واجد X، ردشده Y به تفکیک (لغو، سیاه، بدون رضایت، نامعتبر، سقف فرکانس)، هزینه برآوردی بر حسب پارت پیامک («≈ ۳٬۲۰۰ پیامک») در برابر اعتبار («از ۱۲٬۴۵۰ پیامک»)، ارسال آزمایشی (≤۵ شماره تست)، «آماده‌سازی برای تأیید» (`prepare` → token). اعتبار ناکافی (۴۰۲) = بلاک.

### ۳.۴ تأیید نهایی — `campaign-confirm.html`
مودال قرمز با خلاصه (تعداد، مخاطب، نوع، پیش‌نمایش، نویسه/پارت، زمان)، شمارش معکوس ۱۰ دقیقه (`role=timer`؛ اعلان صوتی فقط در ۱ دقیقه پایانی)، فیلد «برای تأیید، تعداد گیرندگان (X) را تایپ کنید» (مقایسه پس از نرمال‌سازی ارقام و حذف جداکننده)، کد پیامکی ادمین، دکمه‌ها: **«انصراف» با autofocus** و «ارسال برای X نفر» danger که تا تطابق عدد و کد `aria-disabled` است.
حالات: عدد اشتباه، توکن منقضی («دوباره آماده کنید»)، تغییر پس از آماده‌سازی (باطل)، ثبت موفق → «در انتظار تأیید مدیر».

### ۳.۵ تأیید مدیر — `campaign-approval.html`
همان خلاصه + سازنده/زمان؛ «بازگشت» (فوکوس پیش‌فرض)، «رد کمپین» (دلیل الزامی)، «تأیید و شروع ارسال» danger. سازنده = تأییدکننده: دکمه غیرفعال + توضیح (`aria-describedby`). شرط: PROMO یا >۱۰۰۰ گیرنده.

### ۳.۶ اجرای کمپین — `campaign-run.html`
نوار پیشرفت چندبخشی (تحویل/ارسال‌شده/ناموفق/در صف) + badgeهای عددی (اطلاعات فقط با رنگ منتقل نمی‌شود)؛ «توقف اضطراری» و «لغو کمپین» (هر دو با تأیید)؛ حالت circuit breaker «متوقف شد: نرخ خطای بالا» + ادامه؛ پایان.

### ۳.۷ قالب‌ها — `templates.html`
جدول (نام، کلید، نوع، نسخه، فعال) + ویرایشگر: چیپ‌های متغیر مجاز (درج در مکان‌نما)، خطای «متغیر ناشناخته»، فیلد شناسه قالب verify فقط برای OTP، تاریخچه نسخه، ذخیره = نسخه جدید. پایه‌ها: otp.login، order.*، partner.commission.credited/settled، promo.generic.

### ۳.۸ مخاطبان و سگمنت‌ها — `contacts.html`
جدول لیست‌ها (ایستا/پویا، تعداد، آخرین به‌روزرسانی، import در حال پردازش با درصد)؛ سازنده سگمنت (کانال، شهر، تعداد سفارش، آخرین خرید، همکار فروش، برچسب) با شمارش زنده `aria-live`؛ خالی؛ خطای CSV.

### ۳.۹ گزارش‌ها — `reports.html`
فیلترها (بازه، کمپین، وضعیت، نوع، شماره)، جدول با badge و تعداد تلاش، drawer جزئیات با timeline تلاش‌ها، خروجی CSV (ماسک موبایل برای غیرادمین؛ موبایل‌ها در UI همیشه ماسک `0912***4567`).

### ۳.۱۰ لغو و لیست سیاه — `optout.html`
دو تب؛ جدول (موبایل، منبع: پیامک ۱۱/پرتال/ادمین/provider، تاریخ، دامنه همه/تبلیغاتی)؛ افزودن دستی با دلیل اجباری؛ import CSV؛ حذف با مودال تأیید؛ صندوق پیام‌های دریافتی تشخیص‌داده‌نشده (ثبت لغو/نادیده).

### ۳.۱۱ گزارش فعالیت — `audit.html`
جدول فقط‌خواندنی (زمان، کاربر، اکشن، هدف، diff در `<details>`)، جستجو و فیلتر اکشن؛ نمونه ۴۰۳.

### ۳.۱۲ تنظیمات — `settings.html`
ساعات مجاز تبلیغاتی (پیش‌فرض ۰۸:۰۰–۲۱:۰۰، قابل‌تغییر توسط مدیر پیامک/مدیر کل؛ اگر خارج ۰۸–۲۱ شد هشدار زرد «این بازه رسماً تأییدنشده است»)، سقف فرکانس، آستانه هشدار اعتبار (تعداد پیامک)، شماره‌های تست (≤۵)، provider فعال، وضعیت کلیدها «تنظیم شده ✓ / نشده ✗» بدون مقدار، «تست اتصال» با نتیجه.

## ۴. معیارهای پذیرش سراسری

- [ ] ارسال انبوه بدون گذر از بازبینی + مودال + (در صورت لزوم) تأیید مدیر ممکن نیست؛ «انصراف» فوکوس پیش‌فرض.
- [ ] هر خطای API (۴۰۰/۴۰۲/۴۰۳/۴۰۹/۴۲۲/۴۲۹) پیام فارسی مشخص دارد.
- [ ] کلیدها هرگز نمایش داده نمی‌شوند.
