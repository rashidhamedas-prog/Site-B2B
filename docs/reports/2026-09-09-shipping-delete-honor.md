# حذف روش ارسال در تنظیمات تکی ذخیره نمی‌شد

تاریخ: ۲۰۲۶-۰۹-۰۹  
تسک: TASK-20260909-005

## ریشه

«تحویل در محل» (`IN_PERSON`) در TASK-20260908-007 عمداً به **هر** فهرست ذخیره‌شده تزریق می‌شد اگر غایب بود.

زنجیره:

1. ادمین در تب تکی روش را حذف می‌کند و ذخیره می‌زند. PUT آرایهٔ بدون `IN_PERSON` را می‌نویسد.
2. `GET /settings/admin` و `settings.shipping()` از `resolveChannelCompanies` می‌گذرند و دوباره `IN_PERSON` را اضافه می‌کنند.
3. ادمین صفحه را رفرش می‌کند؛ روش برگشته. حس «ذخیره نشد».
4. `GET /shipping/methods?channel=RETAIL` همان فهرست هیدراته‌شده را می‌دهد؛ چک‌اوت `.ir` روش را نشان می‌دهد.
5. اگر پاسخ API خالی می‌شد، `resolveShippingMethods([])` هم به fallback تکی (شامل تحویل در محل) برمی‌گشت.
6. لود ادمین اگر `companies.length` صفر بود، `DEFAULT_RETAIL_COMPANIES` را جایگزین می‌کرد.

ذخیره در DB لزوماً خراب نبود؛ **خواندن** حذف را باطل می‌کرد.

## اصلاح

- فهرست ذخیره‌شده (حتی خالی) مرجع است.
- `IN_PERSON` فقط در پیش‌فرضِ پیکربندی‌نشده می‌ماند.
- ادمین دیگر لیست ذخیره‌شده را به‌خاطر خالی بودن با پیش‌فرض عوض نمی‌کند.
- آرایهٔ خالی از API دیگر با fallback چک‌اوت پر نمی‌شود.
