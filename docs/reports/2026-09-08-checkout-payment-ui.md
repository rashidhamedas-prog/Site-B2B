# بازطراحی UI انتخاب پرداخت — چک‌اوت تک و عمده

تاریخ: 2026-09-08  
تسک: TASK-20260908-003

## هدف

صفحهٔ تسویه که مشتری روش پرداخت را انتخاب می‌کند، در هر دو ویترین یک معماری مشترک و ظاهر بوتیک داشته باشد و CTA پرداخت مبهم نباشد.

## فرض‌ها و محدودیت‌ها

- روش‌های مجاز از قبل در ادمین/API تعریف شده‌اند؛ روش جدید اضافه نشد.
- تکی: زرین‌پال (پیش‌فرض)، دیجی‌پی و ترب‌پی در صورت eligible، پرداخت هنگام تحویل. ترب‌پی از TASK-20260907-002 است؛ کارت فقط وقتی `TOROBPAY` در eligible باشد دیده می‌شود. چک آدرس ۱۰۱۱ زنده حفظ شد.
- عمده: آنلاین (اگر `payment.enabled`)، نقدی، اقساطی با eligibility موجود.
- اعداد و موجودی همچنان روی سرور محاسبه می‌شوند.
- یافتهٔ تحقیق کاربری تازه نداریم؛ الگوی کارت رادیویی + مبلغ روی CTA + نوار چسبان موبایل از [فرض/الگوی صنعت] است نه از تست ترنم.

## معماری

```
checkout-payment-ui.ts     منطق کپی CTA و فهرست گزینه‌ها
CheckoutChoiceList         radiogroup قابل‌کیبورد
CheckoutPanel / StepRail   قاب بخش و لنگر آدرس/ارسال/پرداخت
CheckoutPlaceOrderBar      CTA + اعتماد + حالت چسبان موبایل
```

اسکیل Adobe App Builder / React Spectrum اعمال نشد؛ استک این پروژه Next + Tailwind + توکن برند است.

## تبدیل

- پیش‌فرض آنلاین حفظ شد.
- متن دکمه برای آنلاین شامل مبلغ تومان است.
- روی موبایل CTA همیشه دیده می‌شود.
- دکمه شناور تماس عمده روی `/checkout` خاموش شد تا با پرداخت رقابت نکند.
- نشان «پیشنهادی» فقط روی درگاه پیش‌فرض آنلاین است؛ شمارش معکوس یا کمبود جعلی اضافه نشد.

## امنیت

بدون تغییر adapter، webhook، secret، یا payload `/orders` و `/payments/start`.

## ریسک

اگر نوار چسبان روی گوشی کوتاه با کیبورد تداخل کرد، padding پایین صفحه قابل تنظیم است.
