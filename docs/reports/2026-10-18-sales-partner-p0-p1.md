# همکار بازاریاب — بستن P0 و P1های قطعی — ۲۰۲۶-۱۰-۱۸

## پوشش

| ID | نتیجه |
|---|---|
| P0-01 | پروفایل `NEEDS_INFORMATION` دیگر جلوی ثبت مجدد را نمی‌گیرد. بعد از OTP، درخواست و پروفایل به `PENDING_REVIEW` برمی‌گردند. |
| P0-02 | توکن، وضعیت و شمارندهٔ ارسال فقط بعد از قبول پیامک ذخیره می‌شوند. شکست production لینک قبلی را عوض نمی‌کند. |
| P1-01 | اصلاح `PENDING_OTP` همان رکورد را به‌روز می‌کند. برای `PENDING_REVIEW` و `NEEDS_INFORMATION` نسخهٔ جدید تا موفقیت OTP در `pendingRevision` می‌ماند. |
| P1-02 | شماره و نام مشتری از `localStorage` حذف شد. فقط انتخاب کالا در `sessionStorage` همین زبانه می‌ماند. |
| P1-03 | تنوع انتخاب‌شده با پاسخ دیررس محصول دیگر عوض نمی‌شود. |
| P1-04 | کارت قبل از پیامک کالا، رنگ/سایز، تعداد و مشتری را نشان می‌دهد. مبلغ همچنان از پاسخ سرور است. |
| P1-06 | سقف DTO و سیاست اطلاعیه یکی است: ۱۲۰ / ۲۰۰۰ / ۴۰ / ۵۰۰. متن بلندتر رد می‌شود. |
| P1-07 | شمارش گزارش برنامه و آمار پیش‌نویس از `COUNT` کل جدول است، نه ۵۰۰ رکورد اخیر. فهرست‌های صفحه‌بندی‌نشدهٔ ۱۰۰تایی هنوز باز است. |
| P1-08 | خرابی یک API میز مدیر، داده‌ای را که همان بار موفق آمده پاک نمی‌کند. |
| P1-09 | نام، استان، شهر و نشانی خالی یا فقط فاصله رد می‌شود. کدپستی اگر باشد باید ۱۰ رقم باشد؛ ارقام فارسی نرمال می‌شوند. ادامهٔ پرداخت سفارشِ قبلاً ساخته‌شده به نشانی تازه وابسته نیست. |

## خارج از این انتشار

کد ملی، اثر مالی معرف، تسویه بدون شبا، متن حقوقی شرایط، بازطراحی کامل دو جهت UX، صفحه‌بندی همهٔ جدول‌های مدیر، و فرم‌ساز `select` تصمیم محصول یا کار P2 مانده‌اند. نرخ کمیسیون اختراع نشده است.
